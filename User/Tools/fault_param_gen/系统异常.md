# 系统异常

## 1\. 调研

本文参考了主流关节电机厂商（ODrive, VESC， 行动元，小米CyberGear）的异常处理实践，使故障源枚举值直接对应故障优先级，具有故障分级与处理机制。

## 2\. 故障码编码规范

保持16位故障码编码格式，**故障源编码顺序与故障优先级严格对应**，优先级越高的故障源，其高4位编码值越小。

```Plain Text
0xSLNN
NN低8位: 具体故障编号 (0x00-0xFF)
L 中4位: 故障级别 (0x0-0xF): 优先级：故障级(0x1) > 异常级(0x2) > 警告级(0x3)
S 高4位: 故障来源 (0x0-0xF):优先级：数值越小，优先级越高
```

### 2\.1 故障来源定义（高4位，**按优先级从高到低排序**）

```C
typedef enum {
    FAULT_SOURCE_SAFETY         = 0x1,  // 安全系统(优先级最高)
    FAULT_SOURCE_POWER          = 0x2,  // 电源系统
    FAULT_SOURCE_DRIVER         = 0x3,  // 驱动器
    FAULT_SOURCE_MOTOR          = 0x4,  // 电机本体
    FAULT_SOURCE_ENCODER        = 0x5,  // 编码器/传感器
    FAULT_SOURCE_MECHANICAL     = 0x6,  // 机械传动系统
    FAULT_SOURCE_BRAKE          = 0x7,  // 抱闸/刹车系统
    FAULT_SOURCE_SOFTWARE       = 0x8,  // 软件与算法
    FAULT_SOURCE_COMMUNICATION  = 0x9,  // 通信系统
    FAULT_SOURCE_ENVIRONMENT    = 0xA,  // 环境因素(优先级最低)

    FAULT_SOURCE_COUNT = 10           // 故障源种类数量
} faultSource_e;
```

### 2\.2 故障级别定义（中4位）

```C
typedef enum {
    FAULT_LEVEL_CRITICAL        = 0x1,  // 故障级（立即停机，需断电排查）
    FAULT_LEVEL_EXCEPTION       = 0x2,  // 异常级（降功率运行，需人工干预）
    FAULT_LEVEL_WARNING         = 0x3,  // 警告级（正常运行，需关注趋势）
    FAULT_LEVEL_ALL             = 0x04,  // 所有故障级别   
} faultLevel_e;
```

### 2\.3 优先级判断规则

```C
// 故障优先级比较：返回true表示fault1优先级高于fault2
bool fault_is_higher_priority(faultCode_e fault1, faultCode_e fault2) {
    // 先比较故障源优先级（高4位）
    uint8_t source1 = FAULT_GET_SOURCE(fault1);
    uint8_t source2 = FAULT_GET_SOURCE(fault2);
    if (source1 != source2) {
        return source1 < source2;
    }
    // 同一故障源，比较故障级别（中4位）
    uint8_t level1 = FAULT_GET_LEVEL(fault1);
    uint8_t level2 = FAULT_GET_LEVEL(fault2);
    return level1 < level2;
}
```

## 4\. 故障处理机制

### 4\.1 故障分级处理策略

|故障级别|停机方式|电源状态|允许操作|恢复条件|
|---|---|---|---|---|
|故障级|立即动态刹车|切断主电源|仅允许读取故障日志|排除故障后断电重启|
|异常级|降功率/减速运行|保持供电|允许读取状态和清除故障|故障消除后手动清除|
|警告级|正常运行|保持供电|所有操作允许|自动清除或手动清除|

### 4\.2 故障优先级

当多个故障同时发生时，**直接通过故障码数值大小判断优先级**，数值越小优先级越高：

1. 安全系统故障（0x1xxx）

2. 电源系统故障（0x2xxx）

3. 驱动器硬件故障（0x3xxx）

4. 电机本体故障（0x4xxx）

5. 编码器/传感器故障（0x5xxx）

6. 机械传动故障（0x6xxx）

7. 抱闸系统故障（0x7xxx）

8. 软件与算法故障（0x8xxx）

9. 通信系统故障（0x9xxx）

10. 环境因素故障（0xAxxx）

**同一故障源内**，故障级（0x1xx）\> 异常级（0x2xx）\> 警告级（0x3xx）

### 4\.3 故障恢复流程

1. **故障检测**：各模块独立检测故障，实时上报给故障管理器

2. **故障仲裁**：故障管理器通过比较故障码数值，自动确定最高优先级故障

3. **故障处理**：执行对应级别的处理动作

4. **故障存储**：将故障信息写入非易失性存储器

5. **故障上报**：通过CAN总线向上位机上报故障信息

6. **故障清除**：故障消除后，手动或自动清除故障状态

## 5\. 故障上报与存储

### 5\.1 故障信息结构

```C
typedef enum {
    FAULT_STATUS_ACTIVE,        // 故障活动状态
    FAULT_STATUS_ACKNOWLEDGED,  // 故障已确认
    FAULT_STATUS_CLEARED        // 故障已清除
} faultStatus_e;

typedef struct {
    faultCode_e code;           // 故障代码
    faultLevel_e level;         // 故障等级
    faultStatus_e status;       // 处理状态
    uint32_t first_timestamp;   // 首次发生时间戳(ms)
    uint32_t last_timestamp;    // 最后发生时间(ms)
    uint32_t count;             // 发生次数
    float value;                // 故障发生时的相关数值
    char description[64];       // 故障描述
} faultInfo_t;
```

### 5\.2 故障存储

- 最多存储100条历史故障记录

- 采用循环覆盖方式存储

### 5\.3 故障上报格式

CAN总线故障主动上报帧格式：

- ID：0x180 \+ 电机ID

- 数据长度：8字节

- Byte0\-1：故障代码（小端）

- Byte2\-3：故障发生次数（小端）

- Byte4\-7：故障首次发生时间戳（小端，ms）
