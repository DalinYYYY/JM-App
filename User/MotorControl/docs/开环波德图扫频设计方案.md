# 开环波德图扫频设计方案

> 文档状态：方案确认与第一版编码落地；已按辨识/验证两方向细分功能定位
>
> 适用工程：`JointMotor`
>
> 外部控制命令：`0x76 TEST_SWEEP_FREQ`
>
> 数据上传通道：复用现有 `TRACE_DATA(0xBA)` 高速上传链路

## 1. 目的与范围

本功能用于在电机运行状态下，对指定控制对象施加正弦扫频激励，采集输入和输出波形，由上位机计算并显示幅频、相频特性。

按用途功能细分为两个方向：**方向一（辨识）**在整定前扫被控对象 G(s)，按带宽法换算 PID 初值；**方向二（验证）**在整定后扫闭环回路 T(s)，产出带宽与裕度验收结论。两者共用同一套扫频通道，细分定义见 2.1。

本方案的约束如下：

1. 对外只增加/使用 `0x76 TEST_SWEEP_FREQ`，不增加 Bode 专用启动、停止或结果命令。
2. 原始采样数据使用现有 `TRACE_DATA(0xBA)` 主动上传接口。
3. `TRACE_CONFIG(0xB9)` 不要求上位机显式发送，由固件在处理 `0x76` 时内部调用。
4. 第一阶段测量“被测对象开环频响”，不等同于闭环控制器的环路增益 `L(s)`。
5. 扫频任务运行于控制 ISR 时间基准内，通信只负责配置，不参与实时波形生成。

原始基线中的扫频模式仅生成固定 0.5 N·m、1 Hz 正弦力矩；本轮已替换为可配置的线性/对数逐点扫频状态机，并将 `0x76` 接入专用协议分发和上位机会话。实现仍需按本文第 10 章完成实机安全验收。

## 2. 术语与测量定义

### 2.0 方案确认结论

本次优化后的“`0x76` 负责启停和配置、`0xBA` 负责原始数据上传、上位机逐频点计算”的总体方向可行。当前主格式扩展为 12 字节整数载荷，包含直流偏置；UART 为主要使用链路，经典 CAN 复用既有请求分包。

但“开环”必须按被测对象定义理解，而不是把所有模式都称为电机开环：

* 第一版验收对象为 `TORQUE_TO_VELOCITY`，即电流内环保持闭合、速度环和位置环旁路，测量机械对象的 `速度 / 力矩(或等效 q 轴电流)` 频响。
* `CURRENT_TO_CURRENT` 是电流闭环响应，不能作为机械开环 Bode 图。
* `CURRENT_TO_VELOCITY` 仍包含电流环和力矩常数，只能命名为“电流到速度对象频响”。
* `VELOCITY_TO_POSITION` 旁路位置环但保留速度环，结果是闭环速度环后的位移响应，不是纯机械积分对象。
* `VELOCITY_TO_VELOCITY` 在速度闭环工作点上测试速度参考到速度反馈频响，例如 `10 rad/s + 0.5 rad/s` 扰动。

因此，上位机必须在会话结果中同时保存 `test_mode`、输入/输出通道、单位、PLL/滤波参数和“是否包含闭环”的说明；只有对象定义、带宽和质量检查均通过时，才将频点标记为“可用于建模”。

### 2.1 功能定位：辨识与验证两方向

Bode 扫频按用途细分为两个方向，共用同一套 `0x76`/`0xBA` 通道，区别只在环的配置、注入位置和偏置目的：

- **方向一（辨识，整定前）**：扫被控对象本身，拿到 G(s) 后按带宽法直接换算 PID 初值，不靠试凑。
- **方向二（验证，整定后）**：参数已装上，扫回路表现，确认整定达标。

#### 2.1.1 方向一：辨识 → 整定 PID

**环配置**：被整定的环断开，更内环保持闭环。

- 测机械参数：电流环闭合当转矩源（Iq 注入，编码器测速），速度环和位置环断开。
- 测电气参数：电流环也断（d 轴电压直接注入，静止或堵转）。

**偏置**：机械辨识加小转矩偏置，让轴在粘性摩擦区缓慢爬行，避开静摩擦死区；电气辨识静止即可，只有测电感饱和 L(I) 时才加电流偏置逐点扫。

**速度开环受限的替代**：若机械上不允许速度开环（如立式轴会坠落），可改成闭环成对激励，把 G 从闭环传函 T 和灵敏度 S 中分离，代价是实验与数据处理更复杂。

**参数换算（带宽法）**：

| 环 | 辨识输入 | 参数换算 | 带宽约束 |
|---|---|---|---|
| 电流环 PI | L̂、R̂ | `Kp = ωc·L̂`，`Ki = ωc·R̂`（零点对消对象极点） | ωc ≤ 2π·fsw/10，保守取 fsw/20 |
| 速度环 PI | Ĵ（B̂ 通常忽略） | `Kp = ωv·Ĵ`，零点 `Ki/Kp = ωv/(3~5)` | ωv ≤ ωc/5 |
| 位置环 P | 速度闭环带宽 ωv | `Kp = ωp`，前馈只降跟踪误差、不改特征方程 | ωp ≤ ωv/5（保守）~ ωv/3 |
| 陷波器 | ω̂r 及谐振峰值 | 中心 = ω̂r，深度按峰值，带宽取 ω̂r/10~ω̂r/5 | 惯量比 J2/J1 > 3 时建议必加 |

没有模型时的试凑法（如 Z-N）只做兜底：阶跃激励幅值大、易激发饱和与死区非线性，且相位裕度差，伺服场合不推荐作为主路径。

#### 2.1.2 方向二：验证环

**环配置**：全环闭环，在各环给定端叠加正弦，测对应反馈量，得到闭环传函 T(jω)。

**偏置**：目的只有一个，把工作点钉在线性区。电流环用堵转加 0.3~1.0 倍额定电流偏置；速度环加 10%~30% 额定转速空载偏置；位置环用定位点或匀速跟踪态。

**验收指标**：

| 指标 | 要求 |
|---|---|
| −3dB 带宽 | 实测值与设计值偏差一般在 ±20% 内 |
| 闭环峰值 Mr | 电流环通常 <2 dB |
| 相位裕度/增益裕度 | 由 `L = T/(1−T)` 反推，常见验收线 PM ≥ 45°、GM ≥ 6 dB |

**反推的可靠性限制**：低频段 T≈1，1−T 有效数字不足，噪声被放大；反推结果只在中高频（穿越区附近）可信，给定与反馈必须同源同步采样。

**扩展项**：抗扰刚度扫频（Iq 上注扰动，测 Δω/Δθ）和前馈通道验证也属于这一方向，验证的是“性能”而不只是“带宽”。

**不达标的两种回法**：

1. 曲线形态与模型不符（谐振峰位置不对、低频斜率不对）——模型错了，回到方向一重新辨识；
2. 形态对但带宽或裕度差——参数没调到位，直接在方向二微调。

#### 2.1.3 两方向对照与测试模式映射

| 维度 | 方向一：辨识（整定前） | 方向二：验证（整定后） |
|---|---|---|
| 扫的对象 | 被控对象 G(s) | 闭环回路 T(s) |
| 环的状态 | 被整定环断开、内环闭合 | 全环闭合 |
| 注入位置 | 对象输入端（u_d 电压、Iq 转矩） | 各环给定端 |
| 直流偏置作用 | 避摩擦死区、定工作点 | 定线性工作点 |
| 输出用途 | 换算 Kp、Ki、陷波参数 | 判带宽、Mr、PM、GM |
| 典型激励 | 单频步进或 chirp，可低频慢扫 | 单频步进为主，需平稳 |

一句话：方向一开环扫对象、小偏置避死区，产出的是 PID 参数；方向二闭环扫回路、偏置钉工作点，产出的是验收结论；验证不达标，先分清“模型错”还是“参数差”，再决定回到辨识还是微调。

现有 5 种测试模式在两方向中的定位：

| 测试模式 | 方向 | 环配置 | 输出用途 |
|---|---|---|---|
| `TORQUE_TO_VELOCITY` | 方向一·机械辨识 | 速度/位置环断开，电流环闭合作转矩源 | Ĵ、B̂ → 速度环/位置环参数 |
| `CURRENT_TO_VELOCITY` | 方向一·机械辨识（含电流环） | 速度/位置环断开，电流环闭合 | 含 Kt 的电流-速度对象 |
| `CURRENT_TO_CURRENT` | 方向二·电流环验证 | 电流环闭合 | 电流闭环 T(s) → 带宽/Mr/裕度 |
| `VELOCITY_TO_POSITION` | 方向一·位置对象 | 位置环断开，速度环闭合 | 速度闭环后的位移对象 → 位置环 Kp |
| `VELOCITY_TO_VELOCITY` | 方向二·速度环验证；兼供方向一取 ωv | 位置环旁路，速度闭环工作点 | 速度闭环 T(s) 验收；ωv 供位置环设计 |

方向一的电气辨识分支（d 轴电压注入测 R/L/L(I)）需要 `VOLTAGE_TO_CURRENT` 模式，见 2.3 与阶段 5；方向二的位置环闭环验证 `POSITION_TO_POSITION`（`POS_REF + POS`，全环闭合）已实现；当前电气参数辨识由既有标定模块承担。本方案的逐点步进正弦覆盖两方向的激励需求，chirp 不在第一版（见 4.1）。

### 2.2 开环对象频响

第一阶段采用对象频响定义：

```text
H(jw) = Y(jw) / X(jw)
```

其中 `X` 是扫频激励，`Y` 是对象响应。电流内环可以保持闭合，但被测外环不闭合。

例如：

| 测试模式 | 激励 X | 响应 Y | 测量对象 |
|---|---|---|---|
| `TORQUE_TO_VELOCITY` | 力矩/等效 q 轴电流 | 速度 | 机械对象 |
| `CURRENT_TO_VELOCITY` | q 轴电流 | 速度 | 电流到机械速度对象 |
| `CURRENT_TO_CURRENT` | q 轴电流参考 | q 轴电流反馈 | 电流闭环响应 |
| `VELOCITY_TO_POSITION` | 速度 | 位置 | 积分/位置对象 |
| `VELOCITY_TO_VELOCITY` | 速度参考 | 速度反馈 | 速度闭环响应 |
| `POSITION_TO_POSITION` | 位置参考 | 位置反馈 | 位置闭环响应（全环闭合） |

第一阶段推荐实现 `TORQUE_TO_VELOCITY`。现有 TRACE 通道已能覆盖 `IQ_REF/IQ/VEL_REF/VEL/POS_REF/POS`，无需先扩展电压观测通道。

响应量的有效带宽限制：`VEL` 若由位置差分加低通滤波得到，接近滤波器截止频率的频段会混入滤波器自身的幅值衰减和相位滞后，使 Bode 结果失真。各模式的高频段有效范围受响应量估计带宽限制：

| 响应量 | 带宽限制来源 |
|---|---|
| `VEL` | 速度估计滤波器截止频率 |
| `POS` | 编码器量化噪声（高频段信噪比下降） |
| `IQ` | 电流采样与电流环执行频率 |

上位机应将速度滤波参数随会话记录，并对超出响应带宽的频点给出可信度标记。

### 2.2.1 第一版电机适用性和边界

当前工程的速度反馈来自 PLL/滤波后的机械速度，默认速度估计带宽约为 100 Hz。因此机械扫频不应把 `f_end=100 Hz` 直接当作可信上限；第一版建议：

| 项目 | 第一版要求 |
|---|---|
| 推荐模式 | `TORQUE_TO_VELOCITY`（方向一·机械辨识） |
| 输入定义 | `IQ_REF`；显示时可按 `kt` 和减速比换算为 Nm |
| 输出定义 | `VEL`（rad/s，当前为 PLL 估计值） |
| 推荐频段 | 0.5~30 Hz；完成 PLL 独立校准后可放宽至 50 Hz |
| 频点数 | 每十倍频 8~12 点，最少 2 个整周期测量 |
| 激励幅值 | 从额定峰值电流/力矩的 1%~5% 起步，确认不饱和后再增加 |
| 结果用途 | 机械惯量、阻尼、共振/反共振初筛；不直接用于闭环增益裕量验收 |

当 `f_end` 接近 PLL 带宽时，结果至少要显示“估计器影响”标志；若要覆盖更高频段，应增加未滤波速度或编码器速度观测，并在上位机按观测器传递函数修正，而不是单纯提高上传采样率。

`TORQUE_TO_VELOCITY` 当前 TRACE 上传的是 `IQ_REF`，不是实际轴端力矩。结果表必须同时给出 `IQ_REF` 原始值和换算力矩：

```text
torque_motor = iq_ref * kt
torque_load  = torque_motor * gear_ratio       /* 仅在 kt 定义为电机侧时使用 */
```

若减速比、`kt` 或单位来源不完整，该频点仍可显示 `VEL/IQ_REF`，但不得标记为“Nm 频响”。

### 2.3 不在第一阶段实现的内容

以下属于后续扩展，不在本方案第一版范围内：

- 在闭环加法点注入并直接测量环路增益 `L(s)`；方向二的裕度评估改由 `L = T/(1−T)` 从实测 T(s) 反推（自动分析见阶段 5）。
- 电压矢量到电流的对象频响（方向一电气辨识分支），除非先增加 `UD/UQ` 观测通道。
- 连续 chirp 的在线 STFT 分析。
- 固件端直接输出 Bode 结果点。

## 3. 总体架构

```text

        |
        v
jm_proto_ops.c
        |
        v
motor_mode_test_sweep.c  <---->  motor_loop / system_state
        |                    |
        |                    v
```

模块职责：

| 模块 | 职责 |

| `motor_mode_test_sweep.c` | 扫频配置、状态机、相位累加、频率切换、超时、安全退出和当前周期 `motor_ref_t` |

| PyQt Bode 面板 | 配置 0x76、显示曲线、导出 CSV |

### 3.1 实施前置确认项

以下是实现时必须保持的工程约束；当前代码已完成其中的协议、扫频状态机、TRACE 和上位机主流程：

1. `0x76` 通过专用 `test_sweep` 回调处理，普通 `set_mode` 不承载扫频 ACK。
2. `motor_mode_test_sweep.c` 使用实例化状态机和 32 位 NCO，逐点执行稳定段与测量段。
3. TRACE 必须支持频点边界标志、部分包、排空和会话元数据；容量不足时必须报告溢出而不是静默丢样本。
4. 启动 ACK 使用统一的 8 字节格式，UART 和 CAN 分包重组后的业务层结果一致。
5. 故障、停止、禁用和状态切换都必须触发扫频 ABORT，并清零当前激励。

## 4. 0x76 协议设计

### 4.1 新载荷格式

主启动载荷固定为 12 字节整数格式。UART 直接发送完整载荷；经典 CAN 使用现有多帧分包机制重组后再进入同一业务解析路径。8 字节整数格式仅作为无直流偏置的兼容输入，旧 12 字节浮点格式仅在兼容开关打开时接受。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `control` | 启停、被测对象、扫频方式和选项位 |
| 1 | 1 | `point_cfg` | 对数模式为每十倍频点数；线性模式为总频点数；1Hz 步进模式忽略 |
| 2 | 2 | `f_start_x10` | 起始频率，单位 0.1 Hz |
| 4 | 2 | `f_end_x10` | 结束频率，单位 0.1 Hz |
| 6 | 2 | `amp_raw` | 激励幅值原始值，定标由 `test_mode` 决定 |
| 8 | 2 | `bias_raw` | 有符号直流偏置，定标由 `test_mode` 决定 |
| 10 | 2 | `format_tag` | 固定 `0xB076`，用于识别 12 字节整数主格式 |

`control` 位定义：

```text
bit7      enable       1=启动，0=停止
bit6..4   test_mode    0~7
bit3..2   sweep_mode   0~3
bit1..0   flags        保留选项
```

停止命令允许只发送 1 字节 `control`，其中 `enable=0`，其余字段忽略；也允许发送完整 12 字节，以便统一上位机打包路径。8 字节兼容启动载荷的 `bias` 按 0 处理。

`amp_raw` 的物理单位由 `test_mode` 决定，定标系数随单位切换，避免 u16 量程瓶颈：

| `test_mode` | 名称 | 幅值单位 | 定标 | 量程 |
|---:|---|---|---:|---:|
| 0 | `TORQUE_TO_VELOCITY` | N·m | ×1000 | 0.001 ~ 65.535 |
| 1 | `CURRENT_TO_VELOCITY` | A | ×1000 | 0.001 ~ 65.535 |
| 2 | `CURRENT_TO_CURRENT` | A | ×1000 | 0.001 ~ 65.535 |
| 3 | `VELOCITY_TO_POSITION` | rad/s | ×100 | 0.01 ~ 655.35 |
| 4 | `VELOCITY_TO_VELOCITY` | rad/s | ×100 | 0.01 ~ 655.35 |

说明：电流/力矩单位 ×1000 定标下 u16 量程充足；速度单位 rad/s 数值较大（额定可达 157 rad/s），统一 ×1000 会把幅值上限压到 65.535 rad/s，因此该模式改用 ×100 定标。解析时按 `test_mode` 查表确定定标系数。

`sweep_mode` 定义：

| 值 | 名称 | 说明 |
|---:|---|---|
| 0 | `STEP_LINEAR` | 线性频率逐点扫频 |
| 1 | `STEP_LOG` | 对数频率逐点扫频，第一版推荐 |
| 2 | `STEP_1HZ` | 1 Hz 固定步进逐点扫频，频点数由起止频率决定 |

第一版不实现 chirp；逐点正弦更容易保证稳定时间、采样点数和相位计算的一致性。稳定周期固定 3 周期；测量周期按频率自适应（低频单周期→高频 8 周期，见 5.4），不通过 `flags` 或运行参数扩展。

`test_mode`（bit6..4，3 bit 共 8 值）与 `sweep_mode`（bit3..2，2 bit 共 4 值）中当前只定义了上表所列枚举，其余未定义值一律返回 `OUT_OF_RANGE`，不得按默认值或相近值兜底处理。`flags` 保留位必须为 0，非 0 返回 `OUT_OF_RANGE`。

### 4.2 参数范围建议

固件必须重新校验并限幅，不能依赖上位机：

```text
0.1 Hz <= f_start <= f_end
f_end <= target_loop_sample_rate / 10
f_end <= 链路吞吐允许的上限（见 6.4，按绑定层自动核算）
1 <= point_cfg <= 255（u8 字段）；频点总数 <= 1024；STEP_LINEAR 且 f_start < f_end 时 point_cfg >= 2
amp_raw > 0
预估总时长 T_total <= T_total_max（默认 600 s，见 5.4）
```

对数模式的实际频点数按 `ceil(log10(f_end/f_start) * points_per_decade) + 1` 计算，最后一个点必须钳制/补齐到 `f_end`；线性模式的 `point_cfg` 就是包含起止点在内的总点数；1 Hz 步进模式的实际频点数为 `ceil(f_end - f_start) + 1`，`point_cfg` 不参与。ACK 的 `point_count` 返回固件取整、钳制后的实际值，不能由上位机自行重算覆盖。

建议默认范围：

| 测试模式 | 推荐默认频率范围 | 链路可用性 |
|---|---:|---|
| `TORQUE_TO_VELOCITY` | 0.5 ~ 30 Hz（PLL 校准后可到 50 Hz） | UART / 经典 CAN（f_end ≤ 30 Hz） |
| `CURRENT_TO_VELOCITY` | 0.5 ~ 30 Hz（PLL 校准后可到 50 Hz） | UART / 经典 CAN（f_end ≤ 30 Hz） |
| `CURRENT_TO_CURRENT` | 5 ~ 500 Hz | 仅 UART |
| `VELOCITY_TO_POSITION` | 0.1 ~ 20 Hz | UART / 经典 CAN |
| `VELOCITY_TO_VELOCITY` | 0.1 ~ 20 Hz | UART / 经典 CAN；适合速度环固定工作点 |

幅值还必须受电机参数中的峰值电流、峰值力矩、最大速度和电压限幅约束。

### 4.3 启动与停止语义

`0x76` 的处理规则：

```text
control.bit7 = 1:
    校验配置
    仅 IDLE/READY 状态允许启动
    启动内部 TRACE（若 TRACE 已被 0xB9 手动开启，返回 BUSY，见 6.1）
    进入 RUN_STATE_TEST_SWEEP_FREQ

control.bit7 = 0:
    停止扫频
    停止激励
    进入 TRACE 排空状态
    数据发送完毕后回 READY 或 IDLE
```

载荷长度分支必须按以下规则硬性校验，禁止按内容猜测格式：

```text
len == 12                 完整新格式（启动，`format_tag=0xB076`）
len == 8                  无偏置兼容格式（启动，`bias=0`）
len == 1 && enable == 0   短格式停止
len == 12 && format_tag != 0xB076
                          旧浮点格式，仅在编译开关启用兼容时解析
其余长度（含 len==1 && enable==1、len∈[2,7]、len∈[9,11]）
                          返回 LENGTH
```

收到 `IDLE`、`DISABLE`、`STOP`、`ESTOP` 或故障时，也必须中止扫频。中止后不得继续使用上一频点的激励。

### 4.4 ACK 载荷

启动成功后 `0x76` 应答载荷为 8 字节，供上位机过滤会话、显示进度和预判完成时间；启动请求主格式为 12 字节整数：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | `session_id` | 内部 TRACE 会话 ID，与后续 `0xBA` 包的 `session_id` 一致 |
| 2 | 2 | `point_count` | 校验/取整后的实际频点数 |
| 4 | 4 | `duration_x100` | 预估总时长，单位 10 ms |

规则：

1. 停止命令的 ACK 无载荷，仅返回状态码。
2. 固件在 ACK 中返回的采样率策略（降采样后的实际值）通过首个 `0xBA` 包的 `actual_rate_hz` 体现，ACK 不重复携带。
3. 上位机以 `TRACE_FLAG_LAST` 为完成判据，`duration_x100` 仅用于进度显示，两者不一致时以 `LAST` 为准。

协议层对 `0x76` 使用专用 `test_sweep` 回调返回“状态码 + ACK 缓冲区/长度”；不能把 ACK 塞入普通空载荷应答，也不能让 CAN/UART 两条路径产生不同格式。

### 4.5 兼容性策略

历史协议将 `0x76` 定义为 `{f_start:f32; f_end:f32; amp:f32}`。新协议采用带 `format_tag` 的 12 字节整数主格式，按长度和标记明确区分：

| 固件/上位机组合 | 行为 |
|---|---|
| 新固件 + 新上位机 | 使用 12 字节整数格式，支持 `bias_raw` |
| 新固件 + 旧上位机 | 可选兼容 12 字节浮点格式，并映射为默认 `TORQUE_TO_VELOCITY + STEP_LOG` |
| 旧固件 + 新上位机 | 新格式不可识别时返回 `LENGTH`/`NOT_SUPPORTED`，上位机不得降级执行 |
| 旧固件 + 旧上位机 | 保持旧固件原有行为；新固件不改变旧上位机的兼容路径 |

兼容策略：

1. 将协议次版本提升，例如从 `1.2` 提升到 `1.3`。
2. `READ_DEV_INFO` 的协议版本和 `JM_FEAT_BODE_SWEEP` 用于能力协商。
3. 新固件解析 `len==12 && format_tag==0xB076` 为主格式，`len==8` 为无偏置兼容格式，`len==1 && enable==0` 为停止。
4. 如需兼容旧上位机，新固件可在编译开关控制下解析 `len==12` 且标记不匹配的旧浮点格式；不需要兼容时明确返回 `LENGTH`。
5. 禁止根据载荷内容猜测协议格式，只允许按长度和协议版本分支。
6. 同步更新 `jm_cmd_def.h`、协议 CSV、CAN DBC、Python `cmd_def.py`、`motor_client.py` 和协议说明文档。

`JM_FEAT_BODE_SWEEP` 只能在固件确实编译进扫频协议、状态机和 TRACE 扩展时上报；功能裁剪版本必须清除此能力位，并对 `0x76` 返回 `NOT_SUPPORTED`。不能继续无条件上报能力位，否则新上位机会在不具备完整实现的设备上开放启动入口。

新 12 字节整数格式在 UART 上直接使用；经典 CAN 请求方向复用已有多帧重组，不改变 CAN 仲裁 ID 和串口帧结构。8 字节整数格式保留兼容，偏置默认为 0。扫频数据上传统一走高速 `0xBA` TRACE 接口；CAN 上按现有应答分包发送。

## 5. 扫频状态机设计

### 5.1 状态

```text
IDLE
  -> PREPARE
  -> SETTLE
  -> MEASURE
  -> NEXT_POINT
  -> SETTLE / FINISH

任意运行态 -> ABORT -> DRAINING -> IDLE
```

### 5.2 频率生成

线性逐点（`sweep_mode=0`）：

```text
f[i] = f_start + i * (f_end - f_start) / (N - 1)
```

对数逐点（`sweep_mode=1`）：

```text
f[i] = f_start * 10^(i / points_per_decade)
```

1 Hz 步进逐点（`sweep_mode=2`，适合低频段 1 Hz 间隔精细测量）：

```text
N     = ceil(f_end - f_start) + 1
f[i]  = f_start + i * 1 Hz     /* 末点钳制到 f_end, 频点数由起止频率决定 */
```

`point_cfg` 在步进模式下不参与频点计算，频点数超 1024 或总时长超限时拒绝启动。

相位必须由控制 ISR 的时间基准累加，不能由通信线程更新时间。数值实现采用 32 位定点 NCO 相位累加器，禁止 float 相位直接累加（float 尾数 24 bit，相位不取模时精度随数值增大而退化，长测量下累积误差不可忽略）：

```text
phase_inc = round(f * 2^32 / f_isr)          /* 频点切换时计算一次 */
phase_acc += phase_inc                        /* u32 自然回绕，等效 mod 2*pi */
sin_out   = sinf(phase_acc * 2*pi / 2^32)     /* 使用时转换，或查表 */
```

数值规则：

1. 相位累加器为 u32，自然回绕，无精度退化，无需手动取模。
2. 每个频点切换时相位累加器清零，暂态由 SETTLE 周期吸收；不做跨频点相位连续。
3. 实际激励频率是量化值：`f_actual = phase_inc * f_isr / 2^32`，与标称频率 `f` 存在偏差。
4. TRACE 元数据中的 `phase_inc`/`f_actual_mHz`（见 6.3）必须描述量化后的实际频率，而非只下发标称频率；上位机解调必须使用该实际频率，否则非整周期采样会引入幅相误差。

### 5.3 参考生成位置

保留 `RUN_STATE_TEST_SWEEP_FREQ`，由 `motor_mode_test_sweep_run()` 生成当前周期的扫频参考。

不同模式生成的参考类型：

| 模式 | `motor_ref_t.ctrl_type` | 外环处理 |
|---|---|---|
| `TORQUE_TO_VELOCITY` | `REF_CTRL_TORQUE` | 旁路速度环 |
| `CURRENT_TO_VELOCITY` | `REF_CTRL_CURRENT` | 旁路速度环 |
| `CURRENT_TO_CURRENT` | `REF_CTRL_CURRENT` | 旁路速度环，电流环闭合，测电流闭环响应 |
| `VELOCITY_TO_POSITION` | `REF_CTRL_VELOCITY` | 旁路位置环 |

扫频模块只生成参考，不直接操作 PWM；电流环和半桥输出仍由现有 `motor_loop_isr()`、`cascade_control` 和 `current_loop` 负责。

多电机实例约束：扫频状态机、相位累加器和频点游标全部挂在 `motor_ctrl_t` 实例字段（延续现有 `test_phase`/`test_freq` 的实例化设计，见 [motor_mode_test_sweep.c](../Modes/motor_mode_test_sweep.c)），不使用文件级 static，保证多电机实例可独立扫频。扫频接口第一个参数为 `motor_ctrl_t *`。第一版上位机仅对单电机发起扫频。

### 5.4 扫频时长与超时

低频点是总时长的主要来源。若每个频点固定执行 3 稳定 + 8 测量周期，0.1 Hz 单点耗时达 110 s。为此采用自适应测量周期（已实现，见 [motor_mode_test_sweep.c](../Modes/motor_mode_test_sweep.c)）：

```text
N_meas_eff(f) = max(1, min(N_meas, round(t_meas_max * f)))   /* 低频单周期, 高频过渡到多周期 */
t_point(f)    = (N_settle + N_meas_eff(f)) / f
T_total       = Σ t_point(f[i])
```

参数与规则：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `N_settle` | 3 | 稳定周期数，不封顶（暂态必须充分衰减） |
| `N_meas` | 8 | 测量周期数上限 |
| `t_meas_max` | 2 s | 测量时长基准；各频点测量时长恒约该值（0.5 Hz→1 周期、1 Hz→2、2 Hz→4、4 Hz+→8） |
| `T_total_max` | 600 s | 总时长上限，编译期可配置 |

单周期测量（`N_meas_eff = 1`）下同步解调仅覆盖 1 个整周期，抗噪余量小于多周期点；上位机质量规则同步放宽为"不足 1 个整周期才判无效"，SNR 检查保持不变。

1. 启动校验时固件计算 `T_total`，超过 `T_total_max` 返回 `OUT_OF_RANGE` 拒绝启动；`T_total` 通过 ACK 的 `duration_x100` 返回（见 4.4）。
2. 示例：0.5 ~ 30 Hz、10 点/十倍频（19 点）时，自适应周期下单点测量时长约 2 s，总时长约 60 s。最终时长以固件 ACK 为准。
3. 超时语义（防御性，理论上状态机由周期计数驱动不应触发）：总运行时间超过 `T_total_max + 30 s` 仍未 FINISH 时触发 ABORT，按第 8 节安全流程退出。

## 6. TRACE 高速上传复用

### 6.1 自动配置

收到 `0x76` 启动后，固件内部根据模式自动选择 TRACE 通道：

| 模式 | 通道掩码 |
|---|---|
| `TORQUE_TO_VELOCITY` | `IQ_REF + VEL` |
| `CURRENT_TO_VELOCITY` | `IQ_REF + VEL` |
| `CURRENT_TO_CURRENT` | `IQ_REF + IQ` |
| `VELOCITY_TO_POSITION` | `VEL_REF + POS` |
| `VELOCITY_TO_VELOCITY` | `VEL_REF + VEL` |

采样率策略（已实现，见 [jm_proto_ops.c](../../Protocol/joint_proto/jm_proto_ops.c)）：保底 `20 * f_end`，同时按测试对象设最低采样率——电流环对象（`CURRENT_TO_CURRENT`）不低于 5 kHz，速度/位置对象不低于 2 kHz；超过控制频率（电流环 10 kHz）时钳制到控制频率。采样率还受通信链路吞吐约束，固件按绑定层核算上限并自动降采样，无法满足最低 10 倍采样时拒绝启动，具体策略见 6.4。

会话互斥规则：`0x76` 与 `0xB9` 不允许同时开启 TRACE 会话，互斥但不互相接管——

```text
0x76 启动时 TRACE 已处于 RUNNING（上位机经 0xB9 手动开启）
    -> 返回 JM_ERR_BUSY(0x0C)，不启动扫频
0xB9 启动请求到达时扫频会话处于 RUNNING/DRAINING
    -> 返回 JM_ERR_BUSY(0x0C)，不影响扫频
```

任一时刻最多存在一个 TRACE 会话。扫频正常结束或中止进入 STOPPED 后，`0xB9` 恢复可用。

### 6.2 TRACE 完成排空

现有 `motor_observer_trace_stop()` 会立即清空采样缓存，扫频结束时直接调用会丢失最后一段数据。需要将 TRACE 状态扩展为：

```text
STOPPED -> RUNNING -> DRAINING -> STOPPED
```

新增内部接口或内部状态：

```c
int motor_observer_trace_finish(void);
```

`finish` 只禁止继续写入并置 `LAST` 标志，不清空缓存；通信线程继续调用现有 `trace_pop`，直到缓存为空后再转为 `STOPPED`。

### 6.3 TRACE 扫频元数据

现有 `TRACE_DATA(0xBA)` 已包含 `session_id`、`sequence`、`first_sample_index`、`actual_rate_hz`、`channel_mask` 和 `flags`。为避免上位机依赖时间推算频点，扫频 TRACE 包增加可选扩展：

```text
flags 包含 TRACE_FLAG_SWEEP 时：
    sweep_point:u16
    phase_inc:u32
    f_actual_mHz:u32
```

普通 TRACE 包格式保持不变；只有扫频会话设置该标志。上位机根据标志决定是否读取扩展字段。

新增标志如下。`TRACE_FLAG_LAST(0x04)` 已在 [motor_observer.h](../CascadeControl/motor_observer.h) 中定义并占用 bit2，直接复用，不重复分配：

```text
TRACE_FLAG_SWEEP          0x08   新增：本包携带扫频扩展元数据
TRACE_FLAG_POINT_START    0x10   新增：本包首样本为某频点测量段起点
TRACE_FLAG_POINT_END      0x20   新增：本包末样本为某频点测量段终点
TRACE_FLAG_LAST           0x04   已有：会话最后一包（复用现有定义）
```

`phase_inc` 是 NCO 实际使用的相位增量，`f_actual_mHz` 按 `phase_inc * f_isr / 2^32` 计算后以 1 mHz 定标下发。不能只上传标称频率：0.1 Hz 级别的显示值不足以复现高频点的实际相位，且会使同步解调出现幅相偏差。`sweep_point` 为频点序号（0 起），与 ACK 返回的 `point_count` 对应。

**频点边界是强制协议约束。** 固件不得让一个 `TRACE_DATA` 包跨越两个频点；切换频点前必须先把当前包以 `POINT_END` 发出，下一包从新频点测量段开始并置 `POINT_START`。如果剩余样本不足 `packet_samples`，允许发送不足 8 点的部分包；`trace_pop` 不能再以“缓存点数小于固定包长就不发送”为前提。这样上位机可以只按包元数据分组，不依赖时间推算，也不会把两个频点混入同一段解调数据。

### 6.4 链路预算与采样率上限

通信链路必须满足：

```text
平均发送能力 >= 采样率 * 单点字节数
```

按 2 通道 × 4 B = 8 B/点估算。扫频 TRACE 每包 24 样本（`MOTOR_OBSERVER_TRACE_MAX_PACKET_SAMPLES=24`，2 通道载荷 227 B），含 `0xBA` 扩展包头后折合约 9.5 B/点；普通 TRACE（0xB9）仍按 1~8 样本/包配置，不受影响。各链路的采样率与 `f_end` 上限：

| 链路 | 有效吞吐（估） | 2 通道采样率上限 | 对应 f_end 上限（按 20 倍采样） |
|---|---:|---:|---:|
| UART 2 Mbps | 约 180 KB/s | 10 kHz（控制频率钳制） | 500 Hz |
| 经典 CAN 1 Mbps | 约 8 KB/s | 约 850 Hz | 约 40 Hz |

说明：

1. 本工程 CAN 收发器为 TJA1051 经典 CAN（`USE_CAN_FD_MODE=0` 为硬件约束，无 CAN-FD 能力）；`0xBA` 包在经典 CAN 上需 12 帧左右分包，位填充与帧间隔进一步降低有效吞吐，上表已按保守值估算。
2. 固件按实际绑定层（UART/CAN）在启动校验时核算采样率上限：目标采样率超限时向下取控制频率整数分频值降采样，并在首个 `0xBA` 包的 `actual_rate_hz` 中体现；降采样后无法满足 10 倍 `f_end` 时返回 `OUT_OF_RANGE` 拒绝启动。
3. 由此，`CURRENT_TO_CURRENT`（f_end = 500 Hz，采样率下限 5 kHz）仅在 UART 链路下可执行；经典 CAN 链路下高频模式一律拒绝，低速模式（如 `TORQUE_TO_VELOCITY` 低频段）受 40 Hz 上限约束。
4. UART 独占链路下通信线程单周期循环排空最多 4 包（见 [jm_host_commun.c](../../AppServices/ParamService/jm_host_commun.c)），支撑 2k~10 kHz 采样率的实时上传；稳态下每周期仅 0~1 包，4 包上限用于突发排空防溢出。CAN 链路维持单周期单包，高频扫频溢出按 `OVERFLOW` 标志上报。
5. 发生缓冲溢出时，继续沿用现有 `OVERFLOW/DISCONTINUITY` 标志，上位机必须将受影响频点标记为无效。

### 6.5 缓冲深度扩容

现有环形缓冲 128 点（见 [motor_observer.h](../CascadeControl/motor_observer.h) 中 `MOTOR_OBSERVER_TRACE_BUFFER_SAMPLES`），2 通道 10 kHz 采样下仅约 13 ms 深度，通信任务稍有抖动即溢出；而 Bode 逐点测量是单次顺序流程，溢出频点无法补测，损失不可恢复。

扫频场景将缓冲扩至 512 点（2 通道 × 4 B × 512 = 4 KB RAM），10 kHz 下提供约 50 ms 抖动余量。实施方式在阶段 3 确定：编译期配置区分普通 TRACE（维持 128 点）与扫频 TRACE（512 点），或在 RAM 预算允许时统一扩容至 512 点。扩容后溢出仍可能发生，处理策略不变（见 6.4 第 4 条）。

## 7. 上位机设计

上位机不再主动调用 `trace_config()`；`0x76` 启动请求由固件自动建立 TRACE 会话。当前实现由既有 TRACE 模块、`BodeSession` 和 `BodeAnalyzer` 分工完成：

| 模块 | 主要职责 |
|---|---|
| `core/bode_session.py` | 组包、ACK 校验、会话状态机、TRACE 所有权、超时/中止 |
| `core/bode_analysis.py` | 按频点重组、连续性检查、同步解调、质量评分、CSV 数据模型 |
| `ui/panels/bode_sweep_panel.py` | 参数配置、状态栏、Bode 图、原始波形、频点表和导出操作 |

`JmClient` 只增加 `bode_ack_received`、`bode_trace_received` 或等价的通用分发信号，不把 Bode 分组逻辑塞进传输层。TRACE 接收端必须维护全局所有权 `NONE/PID/BODE`：BODE 会话运行或排空期间，PID 波形窗口禁止发送 `0xB9`；PID 会话已占用 TRACE 时，Bode 面板启动按钮置为不可用。

### 7.1 配置区和会话状态

配置区使用表单而不是自由文本：

| 控件 | 内容与校验 |
|---|---|
| 测试模式 | 下拉项按方向分组前缀标注：【辨识】`TORQUE_TO_VELOCITY`/`CURRENT_TO_VELOCITY`/`VELOCITY_TO_POSITION`、【验证】`CURRENT_TO_CURRENT`/`VELOCITY_TO_VELOCITY`/`POSITION_TO_POSITION`；切换时联动两个结果页的方向提示 |
| 扫频方式 | 对数 / 线性 / 1Hz 步进；对数模式显示“点/十倍频”，线性模式显示“总点数”，步进模式频点自动计算 |
| 起止频率 | 0.1 Hz 分辨率，实时显示链路、PLL 和采样率限制 |
| 激励幅值 | 按模式显示 A、N·m、rad/s 或 rad；显示 `amp_raw` 定标及峰值/额定比例 |
| 预计时长 | 根据 ACK 的 `point_count`、`duration_x100` 更新，不以前端估算覆盖固件结果 |
| 操作 | `启动`、`停止`；运行中只允许停止和导出已接收数据 |

会话状态固定为 `IDLE -> STARTING -> RUNNING -> DRAINING -> COMPLETE`，异常路径为 `ABORTED/ERROR`。状态栏至少显示 session、当前频点/总点数、实际采样率、接收包数、丢包数、溢出数和预计剩余时间。`TRACE_FLAG_LAST` 到达后才进入 COMPLETE；预计时长只用于进度条。

### 7.2 结果页：辨识整定与验证闭环

面板共 5 个 Tab，前两个为方向专属结果页，随频点完成实时刷新：

1. **辨识整定页（方向一）**：
   - 对象拟合：按 `G(s)=1/(J·s+B)` 对全部有效频点做最小二乘拟合（`1/H(jω)` 的实部=B、虚部/ω=J，至少 3 个有效点），显示 J（含 1/Kt 等效）、B、机械转折频率、拟合误差 RMS（>15% 变黄提示）与参与点数。
   - 带宽法 PID 换算：输入目标速度环带宽 ωv → `Kp = ωv·Ĵ`、`Ki = Kp·ωv/4`；输入目标位置环带宽 ωp → `Kp = ωp`（与 J 无关）；修改目标带宽即时重算。
   - 非辨识模式选中时显示“本页不适用”提示。
2. **验证闭环页（方向二）**：
   - 指标表：−3dB 带宽（相对最低频点参考）、闭环峰值 Mr、相位裕度 PM（判定线 ≥45°）、增益裕度 GM（判定线 ≥6dB），PASS/FAIL 红绿着色。
   - PM/GM 由 `L = T/(1−T)` 从实测闭环反推，`|1−T| < 5e-3` 的低频点剔除（噪声放大），L 相位 unwrap 后取 −180° 穿越。
   - 非验证模式选中时显示“本页不适用”提示。

### 7.2.1 波形和 Bode 视图

面板采用上下两块共享对数 X 轴的主视图：

1. **幅频图**：`20 log10(|Y/X|)`，单位 dB；显示有效点实线、无效点空心标记和当前频点竖向游标。
2. **相频图**：`angle(Y/X)`，单位 deg；支持相位 unwrap，保留原始相位列用于复核。
3. **阈值游标**：幅频/相频图各一条可拖动水平游标（默认 −3 dB / −90°），实时标注曲线首次穿越频率，支撑方向二的带宽与裕度读数。
4. **原始波形页**：默认显示扫频全周期输入/输出曲线，按频点分段竖线标注各段激励频率（取自目标激励的 `f_actual`）；点击频点表可切换到单频点测量段视图。
5. **输入/输出单位**：`IQ_REF` 用 A；若电机参数完整，旁边增加换算后的 Nm 曲线，但不替换原始 A 曲线。`VEL` 用 rad/s，`POS` 用 rad。
6. **视图操作**：缩放、平移、跟随当前频点、自动/手动 Y 轴、十字光标读数、复制当前频点数据；暂停只冻结视图，不停止接收和分析。

### 7.3 逐频点分析和质量规则

分析器按 `session_id + sweep_point` 建立频点缓冲，确认 `POINT_START/POINT_END` 后再计算。同步解调优先于普通 FFT，避免低频点因窗口不完整产生泄漏：

```text
X = 2/N * sum((x - mean(x)) * exp(-j*w*n/Fs))
Y = 2/N * sum((y - mean(y)) * exp(-j*w*n/Fs))
H = Y / X
gain_db = 20 * log10(abs(H))
phase_deg = unwrap(angle(H)) * 180 / pi
```

每个频点的数据对象至少包含：`f_actual_mHz`、`phase_inc`、输入/输出峰值和 RMS、复数 `X/Y`、增益、原始/展开相位、SNR、饱和率、包连续性、溢出计数和 `valid_reason`。以下任一条件成立，频点标记为无效并在图上保留空心点：

* 缺少 `POINT_START` 或 `POINT_END`，包序号/样本索引不连续，或 session 不匹配；
* `OVERFLOW`、`DISCONTINUITY` 或中止发生在该频点；
* 输入幅值低于噪声门限、输入/输出出现 NaN/Inf 或达到限幅；
* 测量段不足 1 个整周期，或实际采样率低于 `10 * f_actual`；
* `f_actual_mHz` 与 `phase_inc` 反算值超出允许误差。

SNR 定义为测量频点能量与非相干残差能量之比；SNR 低只降精度、不否定测量——低于 20 dB 标注“SNR偏低”、低于 10 dB 标注“SNR低”，频点仍参与绘图，由用户按频点表取舍。表格中增加“估计器影响”列：下位机 PLL 带宽运行时可调、上位机无法得知准确值，仅已知带宽时按 0.3/0.5 倍分级提示，不据此判无效。

### 7.4 频点表、导出和恢复

频点表列为：序号、标称频率、实际频率、输入 RMS、输出 RMS、增益 dB、相位 deg、SNR、连续性、饱和率、有效性、无效原因。点击一行联动原始波形和图中游标。

CSV 分为两类：

* `*_bode.csv`：一行一个频点，包含实际解调频率、复数幅值、增益/相位、质量字段和有效原因；
* `*_raw.csv`：包含 session、sequence、sample_index、实际采样率、频点、时间戳、输入/输出原始样本。

同时保存 `*_meta.json`，记录固件/协议版本、链路类型、配置原始 12 字节、ACK、通道单位、直流偏置、`kt`/减速比、PLL 参数、采样率、软件版本和接收统计。程序重启后可只读加载这三类文件，不允许把导入数据伪装成当前设备实时会话。

如果暂不实现 TRACE 扩展元数据，不得作为正式验收方案；仅可在虚拟电机测试中按 `actual_rate_hz` 和配置推算频点边界，因为丢包或溢出会导致频点错位。

## 8. 安全与异常处理

固件必须在启动和运行过程中执行以下检查：

- 仅 IDLE/READY 状态允许启动。
- 参数非法、频率超过采样上限时返回 `OUT_OF_RANGE`。
- `test_mode`/`sweep_mode`/`flags` 出现未定义值时返回 `OUT_OF_RANGE`，不兜底。
- 载荷长度不符合 4.3 节分支规则时返回 `LENGTH`。
- 与手动 TRACE 会话冲突时返回 `BUSY`（见 6.1 互斥规则）。
- 预估总时长超过 `T_total_max` 时拒绝启动（见 5.4）。
- 运行中检测过流、过速、母线异常、温度异常和位置越界。
- 运行超时保护：总运行时间超过 `T_total_max + 30 s` 触发 ABORT（见 5.4）。
- 激励或响应出现 NaN/Inf 时立即中止。
- 输出达到限幅时设置当前频点无效标志。
- 通信断开时不应继续依赖主机发送目标；扫频按固件内部状态独立运行，并由故障/超时策略负责停止。
- `STOP/IDLE/ESTOP` 必须优先于扫频状态机。
- 扫频结束或中止后恢复安全参考，不能保留最后一个正弦值。
- 扫频配置只存在 RAM，不写入 Flash。

当前代码路径中不能只“复用已有故障函数”就视为满足上述要求：实施前必须确认 `fault_check()`（或等价保护入口）确实在控制 ISR 的固定周期被调用，并且过流、过速、母线、温度和位置越界能在扫频状态机看到同一个 ABORT 事件。若保护入口只在通信任务或普通运行路径调用，则第一阶段不得放大激励或提高频率；应先补齐 ISR 内实时保护和故障锁存。

扫频参考生成与保护的执行顺序固定为：

```text
读取/锁存 STOP、IDLE、ESTOP 和故障
    -> 执行保护阈值检查
    -> 仅在仍为 RUNNING 时生成本周期 NCO 参考
    -> 写入控制环参考并采集 TRACE
```

保护触发同一控制周期内不得再输出新的正弦参考；下一个安全参考必须为零力矩/零电流或工程既有安全默认值。

### 10.2 实机安全验证

按以下顺序逐步增加幅值和频率：

1. 低幅值、单频点。
2. 低幅值、短频段扫频。

| 指标 | 要求 |

| 频率误差 | 由 NCO 相位量化决定；元数据携带 `f_actual`，上位机解调使用量化值 |

| 结束完整性 | 收到 `LAST` 前最后频点数据不丢失 |
| 安全停止 | STOP/ESTOP 后下一控制周期停止激励 |

| 会话互斥 | 扫频运行中 `0xB9` 返回 BUSY，反之亦然 |
| 兼容性 | 旧固件不误执行新整数格式 |

- 上位机：新增 `BodeSession`、`BodeAnalyzer` 和 `BodeSweepPanel`，显示幅频/相频、当前频点原始波形、频点质量表并导出 Bode/原始数据/元数据 CSV/JSON。
- 上位机交互与分析增强：幅频/相频可调阈值游标（默认 −3 dB/−90°，自动标注穿越频率）；原始波形按频点分段标注激励频率线；PLL 带宽与低 SNR 降级为提示、不再判无效（下位机 PLL 带宽运行时可调，上位机固定假设不合理）。
- 按辨识/验证两方向功能细分落地：固件新增 `POSITION_TO_POSITION`（mode 5，全环闭合位置环验证，`POS_REF|POS` 通道，REF_CTRL_POSITION 注入）；上位机模式下拉按【辨识】/【验证】前缀分组，新增"辨识整定"结果页（`1/H(jω)` 最小二乘 J/B 拟合 + 带宽法 PID 换算）和"验证闭环"结果页（−3dB 带宽/Mr/由 L=T/(1−T) 反推的 PM/GM 及 PASS/FAIL 判定）；虚拟电机按模式合成对应传递函数（机械一阶 8Hz/速度闭环 30Hz/电流闭环 200Hz/位置二阶 8Hz·ζ0.7）。端到端仿真验证：mode 0 拟合转折 7.999Hz（真值 8Hz、误差 0.02%），mode 4 带宽 29.94Hz/PM 90°（真值 30Hz/90°），mode 5 带宽 7.99Hz/PM 65.1°（理论 8.08Hz/65.3°）。
- 虚拟电机：支持 0x76 ACK 和合成 Bode TRACE，用于验证上位机会话和显示链路；合成数据不替代实机安全验收。
- 模式 0 的 TRACE 输入仍是 `IQ_REF(A)`，力矩幅值只是命令定标；没有 `kt`/减速比时结果明确标记为 `VEL/IQ_REF`，不冒充 `Nm` 频响。
- 速度闭环工作点模式使用 `velocity_ref = bias + sweep`，例如 `bias=10 rad/s`、`amp=0.5 rad/s`；上位机和下位机均记录偏置，分析器对测量段去除直流分量后计算交流频响。
