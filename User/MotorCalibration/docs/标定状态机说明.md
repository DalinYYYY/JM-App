# 电机标定状态机说明文档

## 1. 概述

本目录实现了一套**模块化、可扩展**的电机标定框架，采用 C-OOP ops 函数表模式，支持 7 级 27 子模式的标定任务。标定过程异步执行（start 初始化 / poll 周期推进 / abort 中止），符合嵌入式实时约束。

标定作为顶层状态机的一个独立状态 `TOP_FSM_CALIB` 存在，进入该状态后电机控制环不生成运动参考，由标定管理器全权接管周期调度。

## 3. 核心数据结构

### 3.1 标定状态 `calib_state_e`

```
IDLE    ──start()──> RUNNING ──poll()──> DONE     (成功)
                       │                  │
                       │                  └──> FAILED   (失败)
                       │
                       └──abort()──> IDLE
```

| 状态 | 含义 |
|------|------|
| `CALIB_STATE_IDLE`   | 空闲（未开始或已完成） |
| `CALIB_STATE_RUNNING`| 标定进行中 |
| `CALIB_STATE_DONE`   | 标定完成（成功） |
| `CALIB_STATE_FAILED` | 标定失败 |

### 3.2 标定状态快照 `calib_status_t`

| 字段 | 类型 | 说明 |
|------|------|------|
| `state`    | `calib_state_e` | 当前标定状态 |
| `progress` | `uint8_t`        | 进度 0-100 |
| `level`    | `uint8_t`        | 当前标定级别（1-7） |
| `submode`  | `uint8_t`        | 当前子模式 |
| `step`     | `uint8_t`        | 当前步骤（L7 全自动用，单步标定为 0） |

### 3.3 级别模块接口 `calib_level_ops_t`

每个级别模块导出一个 `const calib_level_ops_t` 实例，管理器按 level 索引查表调用：

```c
typedef struct {
    bool           (*start)(uint8_t submode, motor_param_t *param, float dt);
    calib_state_e  (*poll)(void);
    void           (*abort)(void);
} calib_level_ops_t;
```

| 方法 | 调用时机 | 返回值含义 |
|------|----------|-----------|
| `start` | `calib_mgr_start()` 时调用一次 | `false` = submode 不支持，拒绝启动 |
| `poll`  | `motor_control_loop()` 的 CALIB 态每周期调用 | 当前标定状态 |
| `abort` | `calib_mgr_abort()` 或退出 CALIB 态时调用 | 无 |

## 4. 7 级 27 子模式定义

| 级别 | 命令码 | 主题 | 子模式 |
|------|--------|------|--------|
| L1 | 0x90 | 驱动硬件底层 | 1=ADC偏置 / 2=ADC增益 / 3=电流传感器 / 4=温度传感器 / 5=母线电压 / 6=死区特性 |
| L2 | 0x91 | 电机电气身份 | 1=相序识别 / 2=极对数 / 3=R / 4=Ld / 5=Lq / 6=flux |
| L3 | 0x92 | 编码器校准 | 1=零位 / 2=方向 / 3=线性度 / 4=正余弦/旋变 / 5=多圈零点 |
| L4 | 0x93 | 转矩基础 | 1=力矩常数 Kt |
| L5 | 0x94 | 非线性补偿 | 1=齿槽 / 2=摩擦 / 3=死区补偿 / 4=磁饱和 |
| L6 | 0x95 | 负载系统级 | 1=惯量 / 2=阻尼 / 3=回程间隙 / 4=PID自整定 |
| L7 | 0x96 | 自动化集成 | 1=一键全自动 |

子模式常量定义见 [calib_types.h](file:///d:/AAWorkSpace/001_JointMotor/SW/JointMotor/User/MotorCalibration/calib_types.h)（`CALIB_L1_*` ~ `CALIB_L7_*`）。

## 5. 管理器工作流程

### 5.1 初始化

`system_state_init()` 中调用 `calib_mgr_init(param, dt)`，注入电机参数指针和控制周期。

### 5.2 启动标定

协议层收到 0x90-0x96 命令时调用 `calib_mgr_start(level, submode)`：

1. 校验 level 范围（1-7）且当前非 RUNNING 态
2. 查 `s_level_table[level]` 取 ops
3. 调用 `ops->start(submode, param, dt)`，返回 false 则拒绝
4. 置状态为 RUNNING，记录 level/submode

### 5.3 周期推进

`motor_control_loop()` 在 `TOP_FSM_CALIB` 态每周期调用 `calib_mgr_poll()`：

1. 调用 `active_ops->poll()` 获取子状态
2. DONE 时置 progress=100，FAILED 时置 progress=0
3. 状态写回 `sys->calib_state`

### 5.4 查询与中止

- **查询** (0x97)：`calib_mgr_get_status()` 返回完整状态快照，不切状态
- **中止** (0x98)：`calib_mgr_abort()` 调用 `active_ops->abort()` 后清零状态

### 5.5 顶层状态机集成

[system_state.c](file:///d:/AAWorkSpace/001_JointMotor/SW/JointMotor/User/AppServices/StateMachine/system_state.c) 中的集成点：

| 位置 | 动作 |
|------|------|
| `system_state_init()` | 调用 `calib_mgr_init(param, dt)` |
| `top_fsm_switch()` 进入 CALIB | `calib_state = IDLE`, `ref.ctrl_type = REF_CTRL_IDLE` |
| `top_fsm_switch()` 退出 CALIB | `calib_mgr_abort()`, `calib_state = IDLE` |
| `motor_control_loop()` CALIB 态 | `calib_state = calib_mgr_poll()`, 不生成运动参考 |

## 6. 协议交互

| 命令 | 方向 | 载荷 | 应答 |
|------|------|------|------|
| 0x90-0x96 | Host→Motor | `{submode:u8}` | ACK（启动成功）/ NACK(0x0A) 已在标定 / NACK(0x02) submode非法 |
| 0x97 查询 | Host→Motor | 无 | ACK=完成 / NACK(0x0A)=进行中 / NACK(0x03)=未标定 |
| 0x98 中止 | Host→Motor | 无 | ACK |

典型交互流程：

```
Host                         Motor
 │                             │
 │── 0x90 {sub=1} ────────────>│  启动 L1 ADC偏置
 │<── ACK ─────────────────────│
 │                             │
 │── 0x97 ────────────────────>│  轮询进度
 │<── NACK(0x0A) ──────────────│  进行中
 │      ...                    │
 │── 0x97 ────────────────────>│
 │<── ACK ─────────────────────│  完成
 │                             │
 └── 或随时 0x98 中止 ─────────>│
```

## 7. L7 全自动序列编排

L7 维护独立的子标定序列状态机，不依赖 `calib_mgr` 的单例 `active_ops`（避免冲突）。序列定义在 [calib_level7_auto.c](file:///d:/AAWorkSpace/001_JointMotor/SW/JointMotor/User/MotorCalibration/calib_level7_auto.c) 的 `s_sequence[]`：

```
L1.ADC_OFFSET → L1.ADC_GAIN → L1.CURRENT_SENSOR
→ L2.PHASE_SEQ → L2.POLE_PAIRS → L2.RESISTANCE → L2.INDUCTANCE_D → L2.INDUCTANCE_Q → L2.FLUX_LINKAGE
→ L3.ZERO_OFFSET → L3.DIRECTION
→ L4.KT
→ L5.COGGING → L5.FRICTION
→ L6.INERTIA → L6.PID_AUTOTUNE
```

共 16 步，当前步骤通过 `calib_status_t.step` 上报。

## 8. 扩展指南

### 8.1 新增子模式

例：在 L3 编码器校准中增加"磁极识别"子模式。

1. **calib_types.h**：新增子模式常量
   ```c
   #define CALIB_L3_MAGNETIC_POLE  6   /* 磁极识别 */
   ```
2. **calib_level3_encoder.c**：
   - `calib_level3_start()` 的 switch 中加 `case CALIB_L3_MAGNETIC_POLE: return true;`
   - 新增 `poll_magnetic_pole()` 函数
   - `calib_level3_poll()` 的 switch 中加 `case CALIB_L3_MAGNETIC_POLE: return poll_magnetic_pole();`

无需修改其他文件，协议层 0x92 命令的 `payload[0]=6` 自动可达。

**新增 L2 子模式拆分后的真实算法填充流程**（以 R 辨识为例）：

1. `calib_config.h`：确认/调整 `CALIB_CFG_L2_R_TEST_VOLTAGE_V` / `_R_TEST_TIME_S` / `_R_SAMPLE_COUNT`
2. `calib_level2_motor.c`：在 `poll_resistance()` 函数体内替换桩，用 `calib_hw_enter` / `calib_hw_apply_voltage` / `calib_hw_get_*` / `calib_hw_exit` 实现状态机，结果通过 `motor_param_set_r(io->param, R)` 写入
3. 无需修改协议层、管理器、其他 level 文件


### 8.2 注意事项

- 所有级别模块的 `start/poll/abort` 共用模块内的 `static` 变量，**不可重入**。L7 通过自维护序列避免与 `active_ops` 冲突。
- `start()` 返回 false 会被管理器拒绝并回 NACK(0x02)，子模块需严格校验 submode。
- `poll()` 必须非阻塞，单次执行应远小于控制周期（建议 < 50% dt）。
- 当前所有子模式为桩实现（直接返回 DONE），真实算法逐个填充 `poll_*()` 函数即可。
