# 标定体系优化方案

> 文档范围：本次仅针对低阻电机安全、标定结果提交错误、标定依赖状态持久化、测量质量评价、编码器零位与方向边界问题进行优化设计。
>
> 本次暂不处理：已有子模式的桩实现问题，以及 L7 `is_calibrated` 完成标志过于宽松的问题。

## 1. 当前基线与问题范围

当前标定框架采用 `start / poll / abort` 异步接口，由 [calib_mgr.c](../calib_mgr.c) 统一调度，各级算法通过 [calib_hw.c](../calib_hw.c) 施加标定电压和访问编码器。

标定结果同时存在两份运行数据：

1. `motor_param_t`：控制环立即使用的运行期参数；
2. `motor_info_t`：通过 `motor_info_calib_submit_xxx()` 写入的 RAM 参数镜像，之后由上位机 0xEA 命令固化到 Flash。

本次重点问题如下：

| 编号 | 问题 | 影响 |
|---|---|---|
| A | 低阻电机采用最小标定电压保底，但直接电压驱动没有有效电流限制 | 可能导致绕组、功率器件或采样链路过流 |
| B | 标定结果提交返回值被 `(void)` 丢弃 | 运行期显示成功，但参数镜像可能没有更新，错误无法上报 |
| C | `s_done_mask` 仅存在 RAM | 重启后前置依赖状态丢失，已完成标定无法被依赖检查识别 |
| D | 算法只检查有限的有限值/范围，缺少统计质量评价 | 噪声、卡转、采样不同步时仍可能产生“合理但错误”的结果 |
| E | 编码器零位普通算术平均，方向只比较起止角度 | 0/360°边界、跨圈、转速过高或短时卡转时可能误判 |

---

## 2. 优化目标与非目标

### 2.1 优化目标

1. 标定期间建立统一的电压、电流、速度和故障安全闭锁；
2. 任何 RAM 参数提交失败都能转换为明确的 `CALIB_FAIL_FLASH_WRITE`；
3. 标定依赖在重启后能够从持久化数据恢复；
4. 每个关键算法都输出“结果值 + 质量指标 + 失败原因”；
5. 编码器零位采用圆统计，方向采用连续角度解包和多点方向判定；
6. 保持现有 `start / poll / abort` 架构和协议兼容性，优先采用增量改造。

### 2.2 非目标

本次不修改以下内容：

- L1.2~L1.6、L3.3~L3.5、L4、L5.1/L5.2/L5.4、L6 的桩实现；
- L7 一键标定的步骤配置和 `is_calibrated` 总完成语义；
- 0xEA Flash 擦写协议本身；
- 不同编码器芯片的底层 SSI/SPI 帧协议。

---

## 3. 总体设计

### 3.1 建议的数据流

```text
标定启动
  ↓
读取并冻结电机身份快照
  ↓
检查前置依赖与安全条件
  ↓
进入硬件会话
  ↓
限幅后的电压输出 + 实际电流/速度/故障监控
  ↓
采样数据质量评价
  ↓
结果范围校验
  ↓
更新 motor_param_t
  ↓
提交 motor_info RAM 镜像
  ↓
提交失败则标定失败；成功则标记当前子模式完成
  ↓
等待 0xEA 固化 Flash
```

### 3.2 结果状态必须分层

当前 `CALIB_STATE_DONE` 只表示算法函数返回成功，不能区分参数是否已经成功写入 RAM 镜像或 Flash。建议在内部明确区分：

```text
MEASURED       已完成测量，结果通过质量检查
RUNTIME_APPLIED 已写入 motor_param_t
RAM_SUBMITTED  已写入 motor_info_t RAM 镜像
FLASH_PENDING   等待 0xEA 固化
FLASH_SAVED    已由 0xEA 固化成功
```

考虑协议兼容性，第一阶段不必把这些状态全部暴露到 `calib_state_e`，但 `calib_status_t` 至少应增加内部诊断字段或记录最近一次提交状态。

### 3.3 电机身份快照

标定开始时从 [calib_config_runtime.c](../calib_config_runtime.c) 获取一次完整身份快照：

```c
typedef struct
{
    float r;
    float ld;
    float lq;
    float flux;
    uint32_t pole_pairs;
    float peak_current;
    float max_speed;
} calib_motor_ident_t;
```

后续本次标定的：

- 测试电压；
- 电流上限；
- 结果范围；
- 时间窗口；
- 依赖恢复；

均使用该快照，不在一次标定中途重复读取已经被更新的 R/Ld/Lq/Flux。结果确认后，再统一刷新运行参数和持久化镜像。

## 4. 低阻电机过流安全优化

### 4.1 当前风险

低阻电机的配置位于 [calib_config.h](../calib_config.h)：

```c
#define CALIB_CFG_ALIGN_CURRENT_MAX_A 6.0f
#define CALIB_CFG_MIN_CALIB_VOLTAGE_V 3.0f
```

当前 [calib_config_runtime.c](../calib_config_runtime.c) 对低阻电机可能返回 3 V 的最小标定电压。对于 `R = 0.1 Ω` 的电机，扣除死区压降后，理论电流可能达到：

```text
I ≈ (3.0 - 0.5) / 0.1 = 25 A
```

但 [calib_hw.c](../calib_hw.c) 当前主要限制的是：

```c
sqrtf(ud * ud + uq * uq) <= CALIB_CFG_MAX_VOLTAGE_MAG_V
```

这只能限制电压，不能保证绕组电流不超过 `CALIB_CFG_ALIGN_CURRENT_MAX_A`。同时标定电压路径绕过了常规电流环 PI，不能假设运行期电流限幅会自动生效。

### 4.2 安全原则

低阻电机标定必须遵守以下优先级：

```text
实际电流限制 > 电压幅值限制 > 最小电压保底
```

最小电压保底只能作为“提高死区以上信噪比”的候选值，不能绕过电流上限。

### 4.3 推荐的电压计算

对 d/q 轴标定，建议按目标电流和死区补偿估算命令电压：

```text
V_cmd = I_target × R_snapshot + V_dead_comp
```

然后依次执行：

1. `I_target` 不超过标定安全电流上限；
2. `V_cmd` 不超过 `CALIB_CFG_MAX_VOLTAGE_MAG_V`；
3. 施加后读取实际电流；
4. 实际电流超过阈值时立即降压；
5. 降压后仍超限则失败并关闭 PWM。

建议将目标电流分为两类：

```text
CALIB_TEST_CURRENT：R/Ld/Lq/交流注入等测量目标电流
CALIB_ALIGN_CURRENT：零位、极对数、相序、方向等对齐目标电流
```

两者都必须经过同一个最终安全上限：

```c
I_safe = min(I_requested,
             CALIB_CFG_ALIGN_CURRENT_MAX_A,
             motor_peak_current,
             protection_over_current_margin);
```

其中 `protection_over_current_margin` 应低于硬件保护阈值，为 ADC 延迟和控制周期留出余量。

### 4.4 在硬件会话中增加电流监控

建议扩展 [calib_hw.h](../calib_hw.h) 的会话结构：

```c
typedef struct
{
    struct dev_motor *motor;
    float (*orig_ele_cb)(void);
    float forced_ele_angle;

    float current_limit_a;
    float peak_current_a;
    float last_id_a;
    float last_iq_a;
    uint32_t over_current_ticks;
    uint8_t fault;
} calib_hw_session_t;
```

建议增加接口：

```c
bool calib_hw_set_current_limit(calib_hw_session_t *s, float limit_a);
bool calib_hw_check_current(calib_hw_session_t *s);
bool calib_hw_is_faulted(const calib_hw_session_t *s);
```

每次 `calib_hw_apply_voltage()` 后，或每个标定 poll 周期内，应执行：

```text
刷新三相电流
  ↓
Clarke/Park 得到 id/iq
  ↓
I_mag = sqrt(id² + iq²)
  ↓
连续超过阈值若干拍 → 立即置零 PWM并失败
```

建议设置两个阈值：

```text
预警阈值：I_warn = 0.8 × I_limit
故障阈值：I_trip = 1.0 × I_limit
```

瞬时尖峰和持续过流应区别处理：

- 瞬时超过：立即撤销输出；
- 预警持续若干拍：降低电压；
- 故障持续或超过硬件保护阈值：失败并置 `CALIB_FAIL_OVER_CURRENT`。

### 4.5 低阻交流注入的特殊要求

交流注入同时存在 DC 偏置和 AC 分量：

```text
ud = ud_dc + ud_ac × sin(ωt)
```

必须限制最坏情况：

```text
|ud_dc| + |ud_ac| ≤ 允许电压
```

并且不能只分别检查 `ud_dc`、`ud_ac`。建议在 `calib_ac_injection_init()` 中完成：

1. 对 `ud_dc`、`ud_ac` 做幅值检查；
2. 计算最大可能电流；
3. 不满足电流约束时降低 AC 幅值；
4. 降低后仍无法保证安全则返回初始化失败；
5. poll 期间继续监控实际电流。

### 4.6 过流失败的统一收尾

所有以下路径都必须执行相同清理：

```text
CALIB_FAIL_OVER_CURRENT
  → calib_hw_apply_zero()
  → 恢复电角度回调
  → 恢复 calib_raw_mode
  → 清理本级状态
  → 保留 fail_reason
```

不能只返回 `CALIB_STATE_FAILED` 而让后续控制周期继续沿用上一次标定电压。

### 4.7 验收标准

低阻电机安全优化至少应通过以下测试：

| 测试 | 期望结果 |
|---|---|
| R=0.1 Ω、目标 6 A | 实际电流不超过安全阈值，标定可完成 |
| R=0.1 Ω、最小电压计算导致理论电流 25 A | 自动降压或失败，不允许持续输出 |
| ADC 电流反向/异常 | 进入采样异常或过流保护，不写入错误结果 |
| 电机堵转 | 超时或过流失败，PWM 关闭 |
| 取消标定 | 立即置零 PWM，回调恢复 |
| 母线电压异常 | 不启动电压标定，返回安全失败 |

## 5. 标定结果提交错误处理

### 5.1 当前提交链路

以 R 标定为例，当前逻辑大致是：

```c
(io->param)->motor_base.r = R;
(void)motor_info_calib_submit_r(R);
calib_mgr_mark_done(CALIB_LEVEL2_MOTOR, CALIB_L2_RESISTANCE);
return CALIB_STATE_DONE;
```

问题在于 `motor_info_calib_submit_r()` 的返回值被丢弃。

[motor_info_calib.c](../../AppServices/ParamService/motor_info_calib.c) 中的返回约定为：

```text
0   成功
<0  motor_info 未初始化或句柄为空
>0  motor_info 字段范围校验失败，返回对应参数 ID
```

因此当前可能出现：

```text
motor_param_t 已更新
motor_info_t 未更新
标定仍然返回 DONE
完成位已置上
上位机以为结果已经保存
```

### 5.2 必须区分三种“写入”

#### 1. 写入运行期参数

例如：

```c
io->param->motor_base.r = R;
```

作用：当前控制环立即使用。

#### 2. 写入 motor_info RAM 镜像

例如：

```c
motor_info_calib_submit_r(R);
```

作用：更新参数区 RAM 镜像，供协议读取或后续保存。

#### 3. 写入 Flash

由 0xEA 命令执行，作用是掉电保持。

这三者不能混为一谈。标定算法成功后，最多只能说明前两步完成，不能自行声称 Flash 已固化。

### 5.3 提交失败的处理顺序

建议所有标定结果遵循：

```text
计算结果
  ↓
结果质量检查
  ↓
物理范围检查
  ↓
写 motor_info RAM 镜像
  ↓ 失败
CALIB_FAIL_FLASH_WRITE + 不标记完成
  ↓ 成功
写 motor_param_t 运行参数
  ↓
标记子模式完成
  ↓
返回 DONE
```

是否先写 `motor_param_t` 再提交 `motor_info`，需要统一策略。推荐先提交到 `motor_info` 临时镜像，再更新运行期参数，原因是：

- 如果镜像写失败，可以保持运行期旧值，避免两份数据不一致；
- 如果运行期赋值只是普通内存写入，通常不会失败；
- 两份数据完成后再标记 done。

如果工程必须保证标定结果立即用于后续算法，也可以采用：

```text
先更新 motor_param_t
提交 motor_info
提交失败时恢复 motor_param_t 旧值
```

但这需要保存旧值，代码复杂度更高。

### 5.4 建议增加统一提交辅助函数

可以新增 `calib_result_commit.c/h`，统一处理：

```c
bool calib_commit_r(float value);
bool calib_commit_ld(float value);
bool calib_commit_lq(float value);
bool calib_commit_flux(float value);
bool calib_commit_pole_pairs(uint32_t value);
bool calib_commit_encoder_zero(float bias, float offset, int32_t direction);
bool calib_commit_encoder_direction(int32_t direction);
```

辅助函数内部负责：

1. 检查 `motor_info_storage_get()` 是否有效；
2. 调用对应 `motor_info_calib_submit_xxx()`；
3. 将错误码映射为标定失败原因；
4. 记录失败参数 ID，便于诊断；
5. 成功后更新对应 valid mask。

例如：

```c
bool calib_commit_r(float value)
{
    int rc = motor_info_calib_submit_r(value);
    if (rc != 0)
    {
        calib_mgr_set_fail_reason(CALIB_FAIL_FLASH_WRITE);
        calib_mgr_set_submit_error((int16_t)rc,
                                   MOTOR_INFO_PID_PHASE_RESISTANCE);
        return false;
    }
    return true;
}
```

### 5.5 是否要在标定期间直接写 Flash

不建议标定算法每个结果都直接擦写 Flash，原因：

- Flash 擦写耗时；
- Flash 擦写次数有限；
- 可能阻塞通信或控制任务；
- 多个字段逐次保存会产生中间状态。

推荐流程：

```text
每项标定完成：写 motor_info RAM 镜像
全部必要标定完成：上位机发送 0xEA
0xEA 成功：更新 Flash 保存状态
掉电前未 0xEA：下次仍使用上一次 Flash 数据
```

上位机界面应明确显示：

```text
标定结果已生成（RAM）
等待固化
已固化到 Flash
```

### 5.6 失败时是否撤销已经提交的其它字段

建议采用“字段级提交、失败不回滚已成功字段”的策略，但必须：

- 当前失败子模式不置完成位；
- `is_calibrated` 不在本次范围内处理；
- 上位机能读取已更新字段和失败原因；
- 0xEA 保存前，允许用户继续重试失败项；
- 如需事务性全流程，再另行增加 shadow buffer 和 commit 机制。

本次优化不建议引入全量事务回滚，以免扩大改动范围。

## 6. 依赖完成状态持久化

### 6.1 当前问题

[calib_mgr.c](../calib_mgr.c) 当前使用：

```c
static uint64_t s_done_mask = 0;
```

它只记录本次上电后由 `calib_mgr_mark_done()` 设置的完成位。重启后：

```text
s_done_mask = 0
```

即使 Flash 中已经保存了有效的 R、Ld、Lq、Flux、极对数和编码器零位，管理器也无法知道这些项目已经完成。

例如：

```text
第一次上电：完成 L3.1 零位并通过 0xEA 固化
重启
第二次上电：直接启动 L3.2 方向
结果：依赖表看到 L3.1 未在 s_done_mask 中，拒绝启动
```

### 6.2 最小改造方案：启动时从参数推导 done mask

在 `calib_mgr_init()` 或 `calib_mgr_restore_done()` 中读取已经加载好的 `motor_info_t`，根据参数有效性恢复完成位：

```text
pole_pairs 合法       → CALIB_DONE_L2_POLE_PAIRS
R 合法                → CALIB_DONE_L2_RESISTANCE
Ld 合法               → CALIB_DONE_L2_INDUCTANCE_D
Lq 合法               → CALIB_DONE_L2_INDUCTANCE_Q
Flux 合法             → CALIB_DONE_L2_FLUX_LINKAGE
enc_offset 合法       → CALIB_DONE_L3_ZERO_OFFSET
enc_direction=±1      → CALIB_DONE_L3_DIRECTION
```

但该方案有一个限制：

> 仅根据数值无法区分“厂家 profile 默认值”和“实际标定值”。

因此它适合作为兼容旧数据的过渡方案，不是最终方案。

### 6.3 推荐方案：持久化 `calib_valid_mask`

在 `MotorCalibParam_t` 的预留字段中增加：

```c
uint32_t calib_valid_mask;
```

如果需要更多状态，可使用两个 32 位字段：

```c
uint32_t calib_valid_mask;
uint32_t calib_source_mask;
```

建议定义：

```c
#define CALIB_VALID_L1_ADC_OFFSET   (1u << 0)
#define CALIB_VALID_L2_PHASE_SEQ    (1u << 8)
#define CALIB_VALID_L2_POLE_PAIRS   (1u << 9)
#define CALIB_VALID_L2_R            (1u << 10)
#define CALIB_VALID_L2_LD           (1u << 11)
#define CALIB_VALID_L2_LQ           (1u << 12)
#define CALIB_VALID_L2_FLUX         (1u << 13)
#define CALIB_VALID_L3_ZERO_OFFSET  (1u << 16)
#define CALIB_VALID_L3_DIRECTION    (1u << 17)
#define CALIB_VALID_L4_KT            (1u << 20)
#define CALIB_VALID_L5_DEADTIME     (1u << 24)
```

注意：相序当前没有真正结果字段，因此 `CALIB_VALID_L2_PHASE_SEQ` 只能表示“测试通过”，不能表示已写入相序配置。这个位的语义应在代码中明确。

### 6.4 完成位的生命周期

建议流程：

```text
标定成功
  ↓
更新 motor_param_t
  ↓
更新 motor_info RAM 字段
  ↓
设置 calib_valid_mask 对应位
  ↓
0xEA 保存
  ↓
valid mask 与参数一起固化
```

重新标定时：

- 只清除正在重做的子模式 valid bit；
- 清除与其有依赖关系的下游 valid bit；
- 不要无条件清空所有完成位。

例如：

```text
重新做 L2.R
  → 清除 R
  → 清除 Ld
  → 清除 Lq
  → 清除可能依赖 R 的其它派生结果
```

重新做 L3.1 零位：

```text
清除 L3.1
清除 L3.2 方向（方向结果基于零位对齐）
```

### 6.5 启动时恢复

建议新增：

```c
void calib_mgr_restore_done(const motor_info_t *info);
```

由系统初始化在 `motor_info_storage_init()` 和 `motor_profile_sync_to_param()` 之后调用。

恢复逻辑：

1. 优先使用 `calib_valid_mask`；
2. 对旧版本无 valid mask 的数据，按参数合法性做一次兼容推导；
3. 兼容推导完成后不要自动认为是高可信实测值，可标记来源为 `PROFILE_OR_LEGACY`；
4. 后续通过 0xEA 更新为新格式。

### 6.6 依赖关系的维护

当前依赖表位于 [calib_types.h](../calib_types.h)。建议将依赖检查和 valid mask 统一起来：

```c
bool calib_mgr_dependencies_met(uint8_t level, uint8_t submode)
{
    uint64_t required = calib_get_dependency_mask(level, submode);
    return (s_done_mask & required) == required;
}
```

完成位恢复和运行期完成位设置都必须走同一套接口，避免：

- Flash 有效位与 RAM done mask 不一致；
- 某些算法自己设置完成位，某些由管理器设置；
- 重试/重新标定时旧位残留。

## 7. 关键算法的测量质量评价

### 7.1 为什么仅做范围校验不够

当前常见判断形式是：

```c
isfinite(value) && value > 0.0f && calib_validate_xxx(value)
```

它只能排除：

- NaN；
- Inf；
- 明显超范围；
- 负值或零值。

但以下错误结果仍可能通过：

- 电机未动但读到固定噪声均值；
- ADC 饱和后得到稳定错误值；
- 采样窗口相位错误；
- 电流方向反向；
- 速度波动很大但平均值碰巧落在范围内；
- 只有少量有效样本被平均放大；
- 三点拟合点几乎重合但结果数值仍在范围内。

因此每个标定结果应至少包含：

```c
typedef struct
{
    uint32_t sample_count;
    uint32_t valid_count;
    float mean;
    float variance;
    float min;
    float max;
    float excitation;
    float response;
    float quality;
    uint8_t valid;
} calib_measure_quality_t;
```

### 7.2 通用质量检查项

#### 1. 样本数量

```text
valid_count >= minimum_valid_samples
valid_count / sample_count >= minimum_valid_ratio
```

建议不要只检查 `sample_cnt == 0`。

#### 2. 有限性

所有原始采样和中间结果都检查：

```c
isfinite(sample)
```

#### 3. 方差/标准差

```text
variance <= mean² × relative_variance_limit
```

对于均值接近 0 的信号，使用绝对方差阈值。

#### 4. 最大最小跨度

用于识别 ADC 卡死或采样值完全不变：

```text
max - min >= minimum_signal_span
```

注意：信号完全稳定并不一定错误，需结合算法类型决定。比如零位稳定采样希望跨度小，而阶跃/交流注入需要有足够响应。

#### 5. 激励-响应一致性

施加电压/电流后，响应必须满足方向和最小幅值：

```text
sign(response) == expected_sign
abs(response) >= response_min
```

#### 6. 结果重复性

同一测试建议分成两段或多个窗口，分别计算结果：

```text
abs(result_a - result_b) / max(abs(result), epsilon)
    <= repeatability_limit
```

#### 7. 保护状态

只要出现以下任一条件，质量检查失败：

- 过流；
- 超速；
- 编码器错误帧；
- ADC 饱和；
- 母线电压异常；
- 控制环故障；
- 电机未响应；
- 标定会话被中断。

### 7.3 R 标定质量评价

普通阻值两点差分法至少记录：

```text
id_low_mean
id_high_mean
Δid
V_low
V_high
ΔV
R = ΔV / Δid
```

必须检查：

1. `|Δid| >= minimum_delta_current`；
2. `Δid` 的符号与电压差一致；
3. 低档、高档各自样本方差合格；
4. 两个档位的平均值不是 ADC 饱和；
5. `R` 结果满足范围；
6. 两次测试重复结果一致。

建议增加拟合/残差指标。若后续改为 3 点或多点法，可使用：

```text
ud = R × id + V_loss
```

并检查拟合残差。

低阻交流注入法还要检查：

- `sample_cnt` 是否覆盖足够完整周期；
- `i_ac` 是否超过最小可测幅值；
- `phi` 是否处于有效范围；
- R 和 Ld 是否与同一组相敏分量一致；
- 电流相位是否因采样延迟发生明显偏移；
- 电压最大值和实际电流是否超限。

### 7.4 Ld/Lq 阶跃质量评价

阶跃响应不能只累加“有效的 Ld/Lq 点”。应记录：

```text
阶跃电压
初始电流
每拍电流
did/dt 或 diq/dt
估计的时间常数
```

必须检查：

1. 采样窗口在预期暂态范围内；
2. `did/dt` 或 `diq/dt` 不是由噪声造成的尖峰；
3. 有效样本占比足够；
4. 估算出的时间常数与 `L/R` 关系一致；
5. 结果在多个子窗口中重复；
6. 采样结束前没有进入严重饱和。

推荐使用中值或截尾均值：

```text
删除最大/最小的 10%~20% 样本
对剩余样本求均值
```

这样比直接平均更不容易受单点 ADC 异常影响。

### 7.5 Flux 质量评价

Flux 标定必须同时评价：

```text
omega_e 稳定性
iq 稳定性
实际电压稳定性
flux_k 的方差
```

建议：

1. 设置速度稳定窗口；
2. 速度变化率低于阈值后才开始采样；
3. 采样期间 `omega_e` 的相对标准差低于阈值；
4. `iq` 的波动低于阈值；
5. `flux_k` 的正负和范围稳定；
6. 使用多个速度窗口或正反转结果交叉验证。

如果采用默认 Flux 回退值，必须将结果状态记录为：

```text
FALLBACK_DEFAULT
```

不能把回退值与实测值使用同一个“高质量完成”标志。

### 7.6 极对数质量评价

当前极对数算法使用：

```text
pole_pairs = commanded_electrical_angle / measured_mechanical_angle
```

除了结果范围，还应检查：

1. 机械累计角度超过最小阈值；
2. 扫描过程中角度增量方向基本一致；
3. 是否存在明显丢步或突然反向；
4. 由前半段和后半段分别计算出的极对数一致；
5. 四舍五入前的 `pp_f` 距离整数不能过远；
6. 采样期间速度不能超过安全阈值。

建议保留诊断值：

```text
scan_ele_rad
accum_mech_deg
pp_f
pp_rounded
tracking_error
```

### 7.7 质量失败原因建议

现有失败码可以继续复用，但建议按以下规则映射：

| 质量问题 | 失败原因 |
|---|---|
| NaN/Inf | `CALIB_FAIL_SAMPLE_ABNORMAL` |
| 方差过大 | `CALIB_FAIL_SAMPLE_ABNORMAL` |
| 有效样本不足 | `CALIB_FAIL_SAMPLE_ABNORMAL` |
| 激励后无响应 | `CALIB_FAIL_MOTOR_STUCK` |
| 结果超物理范围 | `CALIB_FAIL_OUT_OF_RANGE` |
| 速度超过限制 | `CALIB_FAIL_OVER_SPEED` |
| 电流超过限制 | `CALIB_FAIL_OVER_CURRENT` |
| 编码器错误帧 | `CALIB_FAIL_SAMPLE_ABNORMAL` |
| 超过最大时间窗 | `CALIB_FAIL_TIMEOUT` |

如果上位机需要更细的诊断，可以在 `calib_status_t` 外增加 `detail_code`，不要无限扩充基础失败枚举。

## 8. 编码器零位边界问题优化

### 8.1 当前问题一：角度普通平均会跨 0/360°失败

当前零位采样逻辑是：

```c
calib_step_accumulate(&s_l3.step, calib_hw_get_encoder_raw_deg(m));
float avg_deg = calib_step_average(&s_l3.step);
```

如果采样值为：

```text
359.8°, 359.9°, 0.1°, 0.2°
```

普通平均结果约为 180°，而真实均值应接近 0°。

### 8.2 使用圆均值

建议扩展 `calib_step_t` 或在 L3 中增加：

```c
float angle_cos_sum;
float angle_sin_sum;
```

每次采样：

```c
float rad = deg * PI / 180.0f;
angle_cos_sum += cosf(rad);
angle_sin_sum += sinf(rad);
```

采样完成后：

```c
float avg_rad = atan2f(angle_sin_sum, angle_cos_sum);
if (avg_rad < 0.0f)
    avg_rad += 2.0f * PI;
float avg_deg = avg_rad * 180.0f / PI;
```

### 8.3 圆方差和稳定性

圆均值还应计算集中度：

```text
C = sqrt((Σcos)² + (Σsin)²) / N
```

其中：

```text
C 接近 1：角度集中，采样稳定
C 接近 0：角度分散、转子在动或编码器异常
```

建议增加最小集中度，例如：

```text
C >= C_min
```

具体阈值应通过实际编码器噪声测试确定，不建议直接硬编码未经验证的数值。

### 8.4 采样顺序

建议零位 STEP 3 的顺序改为：

```text
完成采样
  ↓
检查样本数量
  ↓
检查编码器帧有效性
  ↓
计算圆均值与集中度
  ↓
检查圆方差
  ↓
检查 offset 范围
  ↓
提交 motor_info RAM 镜像
  ↓
写入编码器运行时 offset/dir
  ↓
退出硬件会话
  ↓
标记 DONE
```

当前实现是先调用 `set_offset()`，再做范围校验，建议调整为先校验后写入，避免失败路径短暂污染运行期编码器状态。

### 8.5 编码器错误帧

`calib_hw_get_encoder_raw_deg()` 当前通过抽象层读取角度。建议扩展为带状态的读取接口：

```c
bool calib_hw_get_encoder_raw_deg_checked(struct dev_motor *m,
                                          float *raw_deg,
                                          uint32_t *error_flags);
```

至少检查：

- SPI/SSI 通信错误；
- CRC/parity 错误；
- 磁场弱/强异常；
- 角度越界；
- 连续重复帧过多；
- 读取超时。

错误帧不得参与圆均值计算。

## 9. 编码器方向边界问题优化

### 9.1 当前问题一：只比较起止角度

当前方向标定在开始时记录一个角度，结束时再读取一次：

```c
start_angle = calib_hw_get_encoder_mech_angle(m);
...
end_angle = calib_hw_get_encoder_mech_angle(m);
delta = end_angle - start_angle;
```

然后只用 ±180° 修正一次跳变。这无法可靠处理：

- 测试期间转过超过 180°；
- 机械角跨越 0/360°多次；
- 电机先动后卡住；
- 噪声导致起止点方向与实际运动方向相反；
- 电机转动量接近一个整圈。

### 9.2 使用连续角度解包

方向测试期间每个 poll 周期读取一次角度：

```c
float current = get_mech_angle();
float delta = current - previous;

if (delta > 180.0f)
    delta -= 360.0f;
else if (delta < -180.0f)
    delta += 360.0f;

accumulated_delta += delta;
previous = current;
```

建议在 L3 状态结构中增加：

```c
float dir_prev_angle;
float dir_accum_delta;
float dir_positive_delta;
float dir_negative_delta;
uint32_t dir_sample_count;
uint32_t dir_valid_count;
```

### 9.3 方向判定规则

不要只看最终累计值，建议同时检查：

```text
|累计角度| >= 最小有效位移
正向增量比例或反向增量比例达到一致性阈值
反向抖动总量不能过大
测试期间没有编码器错误帧
累计速度不超过安全上限
```

例如：

```text
dir_accum_delta > +min_delta 且正向样本占比 >= 70% → CW
 dir_accum_delta < -min_delta 且反向样本占比 >= 70% → CCW
否则 → MOTOR_STUCK 或 SAMPLE_ABNORMAL
```

70% 仅为结构示例，最终阈值需要根据编码器噪声、采样周期和电机速度实测确定。

### 9.4 起步检测和卡转检测

方向标定不应一直等到固定时间结束才知道电机没有运动。可以加入：

```text
起步窗口：若若干拍累计位移小于阈值，判定未起步
运行窗口：累计位移方向必须稳定
最大测试时间：超过则 TIMEOUT
```

这样可以更早发现：

- 对齐电流不足；
- 死区补偿不足；
- 负载卡死；
- 编码器没有更新。

### 9.5 方向写入顺序

方向标定完成后建议遵循：

```text
计算连续累计角度
  ↓
通过最小位移和方向一致性检查
  ↓
检查结果只能为 +1/-1
  ↓
提交 motor_info RAM 镜像
  ↓
写入编码器运行时方向
  ↓
退出硬件会话
  ↓
标记 DONE
```

如果 `motor_info_calib_submit_enc_direction()` 失败，不应先把运行时方向切换成新值，或者需要保存旧方向并在失败时恢复。

### 9.6 与零位的依赖

方向标定依赖零位对齐是合理的。重新做零位时，应同步清除方向有效位：

```text
重新标定 L3.1 零位
  → 清除 L3.1 旧完成位
  → 清除 L3.2 方向完成位
  → 重新执行零位
  → 再执行方向
```

否则方向结果可能仍是基于旧零位的历史数据。

## 12. 验收用例

### 12.1 低阻电机

- `R=0.1 Ω`，标定目标 6 A；
- 最小电压保底导致理论电流大于上限；
- 实际输出必须自动限压；
- 连续过流必须失败；
- 失败后 PWM 为零，电角度回调恢复；
- 后续查询返回 `CALIB_FAIL_OVER_CURRENT`。

### 12.2 提交失败

模拟以下情况：

- `motor_info_storage_get()` 返回空；
- 参数范围检查失败；
- 指定参数 ID 不可写；
- 提交函数返回非零。

期望：

```text
标定 FAILED
fail_reason = CALIB_FAIL_FLASH_WRITE
子模式完成位不置位
运行期和 motor_info 的一致性符合设计
```

### 12.3 重启依赖

1. 完成 L3.1 并 0xEA 固化；
2. 重启；
3. 不重复 L3.1，直接启动 L3.2；
4. 期望依赖检查通过。

重新标定 L3.1 后：

```text
L3.1 旧位清除
L3.2 旧位清除
```

### 12.4 零位跨界

模拟编码器采样：

```text
359.8°, 359.9°, 0.0°, 0.1°, 0.2°
```

期望零位结果接近 0°，不能得到约 180°。

### 12.5 方向跨圈

测试期间让电机跨越 0/360° 多次，期望：

- 连续角度累计正确；
- 方向不受角度回绕影响；
- 不依赖单个起止角度差。

### 12.6 噪声和异常采样

- 注入 NaN/Inf；
- 注入单点尖峰；
- 固定 ADC 值；
- 编码器连续重复帧；
- 速度大幅波动。

期望质量检查拒绝异常结果，且不写入参数。

## 13. 结论

本次优化的核心不是增加更多标定项目，而是先把已有 L2/L3 标定流程变成可控、可诊断、可恢复的工程流程：

1. **低阻电机必须以实际电流限制为第一安全边界，不能只做电压限幅。**
2. **标定结果提交必须检查返回值，RAM 更新和 Flash 固化必须分层表达。**
3. **依赖完成状态不能只放在 RAM，应持久化 valid mask 并在启动时恢复。**
4. **范围校验不能替代质量评价，需要样本数、方差、重复性、激励响应和保护状态检查。**
5. **编码器零位必须使用圆均值，方向必须使用连续角度累计。**

完成上述优化后，再继续扩展桩子模式和调整 L7 完成标志，整体标定体系会更容易验证，也不会把测量异常静默写入控制参数。
